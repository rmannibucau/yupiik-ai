= Iteration guards: exploration plateaus and window caps
:minisite-breadcrumb: Home[index.html] > Features > Iteration guards
:minisite-nav-prev-link: todo-guidance.html
:minisite-nav-prev-label: Todo and plan guidance
:minisite-nav-next-link: prompt.html
:minisite-nav-next-label: Prompt templates

The agent loop bounds how long a single turn can run and stops models that spin
without making progress. Three guards cooperate, split by what they cover:

* the *doom-loop* guard refuses repeated identical *state-changing/bash* calls
  that keep returning the same already-known result;
* the *exploration-plateau* guard stops *read-only* rounds that keep re-covering
  files/results the turn already read, even when every call signature is
  different (added for flash-class models such as `deepseek-v4-flash`, whose
  native style is one small novel tool call per round);
* the *no-progress* guard (plus the turn-level output tombstone) is the backstop
  for any round, read or not, that repeats known output without new information.

Each guard is configured with a three-level cascade: per-model
(`yca.provider.<id>.models[i].behavior.*`) wins over per-provider
(`yca.provider.<id>.tuning.*`) wins over the global default (`yca.llm.*` for the
plateau, `yca.tools.*` for the doom-loop).

== Exploration plateau

A read-only tool round re-covering only *already-seen* files/results is not
progress: the model explores the same targets with slightly different queries
(different `offset`, `limit`, grep pattern or bash fingerprint) instead of
learning something new. After `plateauRounds` consecutive such rounds the turn
stops with an *Exploration plateau* error, instead of burning the whole
iteration window on redundant reads.

What counts as "already seen" is per turn and keyed by:

* `read`: merged intervals of delivered line numbers or directory-entry positions per normalized absolute path, not 2k offset buckets;
* `grep`: the pattern plus the searched root (a new search is novel);
* `bash`: derived from the configured read-only bash rules
  (`yca.permissions.bash.rules`): the matched rule prefix plus the segment
  target (so a rule added there - eg. `jq` - is automatically protected, there
  is no hardcoded command list); tokens after a redirection are not coverage;
* `glob` / `list_dir`: the normalized root path.

Read coverage records only ranges actually delivered to the model: truncated or otherwise unreturned ranges are not marked seen.
Overlapping or adjacent delivered intervals are merged per path, so advancing into an unseen range is novel even within a previously read 2k offset bucket.
Unknown response formats are handled conservatively, without assuming that a requested range was delivered or already seen.

A round is a plateau round only when it contains a nonempty set of pure, successful, classified exploration calls and every covered range or key was already seen.
Mixed rounds containing failures, pending or refused calls, writes, mutating bash, or unclassified calls reset the streak.
New coverage also resets the streak immediately, and the guard is skipped while pending todos exist (the todo auto-continuation is the intended escape hatch there).

[NOTE]
====
`plateauRounds` has three modes: `0` disables the guard entirely, a positive value is the *nudge + hard-stop* limit, and a **negative** value switches the guard to *nudge-only*: the plateau can emit a feedback nudge but never hard-stops the turn, so a capable model keeps going until it genuinely decides its turn is over (Codex-compatible round semantics).
The nudge-only mode is explicit-only - set it per model/provider, never as the implied default.
====

== Feedback before the stop

With the built-in default (`plateauFeedback=nudge_2`) the model gets **one
chance to adapt** before the hard stop: when the plateau streak reaches
`limit-2` a strategy-change user message is injected ("Stop re-reading: use the
information you already collected, batch any remaining independent reads or
searches into a single reply..."). If the model then reads new files or writes,
the streak resets and the turn continues; if it keeps re-reading, the turn is
stopped at the limit exactly as without the nudge. `nudge_1` sends the same
nudge later (at `limit-1`, for models that profit from a last-minute hint);
`none` disables the feedback entirely and the turn is hard-stopped at the limit
with no model feedback (the pre-existing behavior).

In nudge-only mode (a negative `plateauRounds`) the feedback fires when the streak reaches the absolute value of the limit, at most once per turn, but no hard stop ever follows.
`plateauFeedback=none` suppresses this nudge too, so nudge-only mode with feedback disabled neither nudges nor hard-stops.

[source,properties]
----
# global default (built-in): nudge_2 - nudge at limit-2, then hard stop at limit
yca.llm.plateauFeedback=nudge_2

# per-provider: nudge later (at limit-1)
yca.provider.<id>.tuning.plateauFeedback=nudge_1

# per-model: no feedback, hard stop only
yca.provider.<id>.models.0.behavior.plateauFeedback=none
----

[source,properties]
----
# global default (built-in): 8, 0 disables the guard entirely
yca.llm.plateauRounds=8

# per-provider
yca.provider.<id>.tuning.plateauRounds=5

# per-model (wins over the provider and the global)
yca.provider.<id>.models.0.behavior.plateauRounds=3

# per-model: nudge-only, never hard-stop (capable models)
yca.provider.<id>.models.0.behavior.plateauRounds=-1
----

== Doom-loop guard

The *doom-loop* guard refuses repeated identical *state-changing/bash* tool calls
that keep returning the exact same already-known result, so a model spinning on
one command cannot burn the whole turn on duplicate information. Read-only
tools are deliberately *not* covered: they are owned by the exploration-plateau
guard (semantic re-coverage), so a read is never signature-refused here - only a
repeated state-changing call can trip the doom-loop breaker.

An execution counts toward the guard only when the same tool + the same
normalized arguments **succeeded *and* produced identical output**.

Key semantics:

* **Failures are never counted** - a failing call is a legitimate retry, resets
  the success streak, and is never refused.
* **Fresh content resets the streak** - the same call returning different output
  (polling a changing state) restarts the count, so legitimate progress is never
  refused.
* **Identical timestamps and durations count as identical output** - outputs that
  differ only by an embedded ISO-8601 date/time, a clock time, or an elapsed
  duration maven/gradle emit (`in 5s`, `Total time: 1.234 s`, `0.5ms`) are
  treated as the same result, so a command re-run that only changes its log time
  is still detected as a repeat. Bare digit runs (versions, build ids, checksums)
  are *never* stripped, so genuinely different numbers are not conflated.
* **Refusals are strategy nudges, not errors** - a refused call never runs and is
  surfaced to the model as a one-shot strategy-change directive (like the plateau
  nudge), never as a failed tool result that would read as "retry it". After the
  nudge, further identical calls are withheld and feed the no-progress backstop.
* **T means T** - the threshold is the number of identical-output successes
  observed before the next identical call is refused: with `repeatSuccessThreshold=3`
  the first three run and the fourth is refused.
* **Turn-level output tombstone** - a normalized output already produced this turn
  by *any* tool (even a different one) is treated as non-novel for the
  no-progress/plateau decision, catching `ls`, `find`, `grep` and similar breath
  that all yield the same content. The tombstone only steers the no-progress
  guard; it never produces a hard refusal by itself.

`repeatSuccessThreshold` uses the same three-level cascade as the other guards:
per-model wins over per-provider wins over the global default; `0` at the global
level disables the guard entirely.

[source,properties]
----
# global default (built-in): 3, 0 disables the guard entirely
yca.tools.repeatSuccessThreshold=3

# per-provider
yca.provider.<id>.tuning.repeatSuccessThreshold=5

# per-model: a flash/small model that repeats more stubbornly is caught sooner
yca.provider.<id>.models.0.behavior.repeatSuccessThreshold=2
----

== Iteration window cap

`yca.llm.maxIterations` (default 250) bounds one iteration window: each model round consumes one iteration, including text-only responses handled by the round gate.
When the budget runs out the loop stops, unless an explicit todo auto-continuation starts a fresh window.
Plateau, exploration, and doom-loop nudges and the `turnContinuesOnTextEnd` round gate all share the current window; none resets its budget.
Only an explicit todo auto-continuation starts a new window within the turn.
The cap can be raised for a specific provider or model without touching the global default, or turned off entirely:

[source,properties]
----
# global (built-in): 250
yca.llm.maxIterations=250

# per-provider
yca.provider.<id>.tuning.maxIterations=500

# per-model
yca.provider.<id>.models.0.behavior.maxIterations=500

# per-model: unbounded window - run until the model genuinely finishes
yca.provider.<id>.models.0.behavior.maxIterations=-1
----

A negative value makes the window **unbounded**: the turn runs until it
genuinely ends (the model finishes, a plateau/no-progress guard stops it, the
context overflows, or the turn is cancelled), bounded only by those other
guards - there is no iteration budget. This pairs naturally with the round gate
(`behavior.turnContinuesOnTextEnd=true`) for capable models: a text-only end
keeps re-asking until the work is done, and the unbounded window means the turn
is never cut off mid-run by an iteration cap. Use it with capable models you
trust to finish; small/flash models that can spin should keep a positive cap.

Sub-agents inherit the same provider/model resolution, so a per-model cap applies
to them too - a positive sub-agent window cap always bounds a sub-agent's window
even when its model sets `maxIterations < 0`.

== Persisted stop notices

When the loop stops on an exhausted window (or on an exploration plateau), a
display-only notice is appended to the session with role `system` - for example
`Maximum iterations reached (250): turn stopped; resume starts a fresh window.`
These entries are *never* sent to the LLM (they are filtered out of the working
history) but are rendered in the transcript on replay, so a capped turn no
longer looks like one seamless run. Resuming after such a notice emits an
informational "resuming after an iteration-cap stop" notice.

== Model tuning by family

How a model ends its turn, and how much slack each guard gives it, varies a lot
across model families. yca lets you tune this per provider/`models[i]` entry so
you can pick the right spirit for each model instead of one global setting.

* **Capable agentic models** (`codex`, deepseek-r1, ...) are trustworthy enough
  to keep driving tools until the work is done. For them enable the Codex-style
  *round gate* (`behavior.turnContinuesOnTextEnd=true`): a text-only reply that
  leaves the todo list unfinished no longer ends the turn and waits for
  `continue` - the loop re-asks the model to act on the next item, bounded by the
  iteration window. Turn the exploration plateau into *nudge-only*
  (`behavior.plateauRounds=-1`) so redundant reads remind without risking losing
  a deep search mid-way, and give the *novel-spiral nudge* more room
  (`behavior.explorationNudgeRounds=20`). Set `behavior.maxIterations=-1` for an
  unbounded window so the round gate is never cut off by an iteration cap.
* **Flash / mid models** (`deepseek-v4-flash`, `glm-5.3-flash`, ...) read one
  small novel call per round and genuinely need the plateau hard-stop to avoid
  spinning. Keep a positive `plateauRounds`, leave `turnContinuesOnTextEnd`
  unset (they narrate-and-stop and hand control back), and keep the window the
  default.
* **Small models** (`qwen3-coder`, ...) benefit from `yca.todos.continueOnUnfinished`
  to keep a long task going across text-only ends, but should not enable
  `turnContinuesOnTextEnd`: they stop and wait for instructions, and the plateau
  stays a positive hard-stop.

[NOTE]
====
`turnContinuesOnTextEnd` is explicit-only and defaults to **off for every
model**: without it, a text-only end with unfinished todos surfaces the
`send 'continue'` banner exactly as before. There is no automatic detection of
"capable" models and no global default change - you opt each model/provider in.
====

The samples below are JSON (the provider/model `behavior` block maps to
`yca.provider.<id>.providers[i].models[j].behavior` in the flat configuration
scheme).

*Small model - todo auto-continue, no round gate, plateau hard-stop:*

[source,json]
----
{
  "todos": {
    "continueOnUnfinished": true,
    "maxContinues": 25
  },
  "provider": {
    "providers": [
      {
        "id": "qwen",
        "model": "qwen3-coder",
        "models": [
          {
            "model": "qwen3-coder",
            "behavior": {
              "plateauRounds": 8
            }
          }
        ]
      }
    ]
  }
}
----

*Flash models - need the plateau hard-stop, current maxIterations, no round gate:*

[source,json]
----
{
  "provider": {
    "providers": [
      {
        "id": "deepseek",
        "model": "deepseek-v4-flash",
        "models": [
          {
            "model": "deepseek-v4-flash",
            "behavior": {
              "plateauRounds": 10
            }
          }
        ]
      },
      {
        "id": "zhipu",
        "model": "glm-5.3-flash",
        "models": [
          {
            "model": "glm-5.3-flash",
            "behavior": {
              "plateauRounds": 10
            }
          }
        ]
      }
    ]
  }
}
----

*Capable model - round gate on, plateau nudge-only, roomier exploration and an unbounded window:*

[source,json]
----
{
  "provider": {
    "providers": [
      {
        "id": "codex",
        "model": "gpt-6-codex",
        "models": [
          {
            "model": "gpt-6-codex",
            "behavior": {
              "turnContinuesOnTextEnd": true,
              "plateauRounds": -1,
              "explorationNudgeRounds": 20,
              "maxIterations": -1
            }
          }
        ]
      }
    ]
  }
}
----
