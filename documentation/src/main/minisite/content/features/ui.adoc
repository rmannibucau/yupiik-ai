= Interactive UI and headless mode
:minisite-breadcrumb: Home[index.html] > Features > Interactive UI and headless mode

yca can be driven through two interactive frontends or in a single-shot headless
mode.

The xref:../cli/tui.adoc[`tui`] command opens a full-screen interface: markdown
transcript, token gauges, a streaming thinking view, approval modals, todos and
an editable plan (`/editplan`).

The xref:../cli/cli.adoc[`cli`] command is a plain-terminal REPL with the same
agent underneath: streamed ANSI-colored output, sessions, todos, approval and
feedback gates and the same slash commands.

For automation, the xref:../cli/run.adoc[`run`] command executes a single
headless prompt and prints the result on stdout. It exits non-zero on failure,
making it easy to call from scripts and CI.

== Speaker labels

The transcript headers (the `▌` line opening every user and assistant turn) are
configurable through `yca.labels`:

[source,json]
----
"labels": {
  "userTemplate": "{{systemProperty \"user.name\" \"You\"}}",
  "assistantTemplate": "{{model.provider}}::{{model.name}}"
}
----

Both are Handlebars templates. The context keys are `userName`
(`System.getProperty("user.name")`, missing values are skipped), `modelName`,
`model` (`name`, `provider`), `provider`, `agent` (the active custom agent or
empty), `mode` (`plan`/`build`), `sessionId` and `configuration` (the whole yca
configuration map). The `systemProperty` helper reads a system property with an
optional default: 1 argument ({`{{systemProperty "user.name"}}`}) renders the
value or nothing when the key is absent, 2 arguments
(`{{systemProperty "user.name" "You"}}`) add the fallback. A template rendering
blank falls back to `You`/`Assistant`.

[IMPORTANT]
====
Speaker labels are strictly a UI feature: they only decorate the rendered
transcript headers. The LLM conversation always keeps its hardcoded
`user`/`assistant` roles (the session store and the wire payload stay
label-free), the compaction summaries keep their `[Assistant]:` /
`[Assistant tool call]:` prefixes and subagents keep `Assistant: ` regardless of
these templates. Changing the active model only changes what headers display,
never what the model receives.

The producing identity (provider, effective model, agent) is captured on every
written block (main loop and subagents alike) and stored with the session
entry. A `/resume` or a template change re-renders each block from its own
identity, so a block written under `M1` is never relabeled `M2` when the model
is switched later.
====

== Side questions (/btw)

While a turn runs, `/btw <question>` asks a side question without interrupting
the running turn.
The question is an orphan by design: it is not added to the conversation, not
persisted to the session and not echoed to the transcript, so the next turns
never see it.
The answer inherits the session history (minus the reply being streamed) and
runs with a bounded read-only tool loop: the model can read files, search and
run plan-mode commands (the same global bash allow-list used in plan mode, so
a refused command simply means "not allowed"), and it is never granted
write access or permissions-all mode.
Mutating commands trigger the approval gate like any other command in the
session, but the side loop stays bounded and keeps the turn running.
The last few side questions are replayed to the model so follow-up side
questions stay coherent.
In the xref:../cli/tui.adoc[`tui`] the answer opens a modal titled `btw`:
the mouse wheel or `Up`/`Down` scroll it, `Esc` closes it and cancels the
request if still running, and the main turn keeps streaming underneath.
In the xref:../cli/cli.adoc[`cli`] the answer is printed inline as a delimited
block once ready.

[opts=headers]
|===
|Property |Default |Description

|`yca.slashcommands.btw.model`
|provider model
|Model answering side questions when set, the session model otherwise.

|`yca.slashcommands.btw.maxTokens`
|0
|Maximum output tokens of an answer, 0 follows the provider/model budget.

|`yca.slashcommands.btw.maxHistoryMessages`
|200
|Most recent session messages inherited as context, 0 keeps everything.

|`yca.slashcommands.btw.recall`
|5
|Previous side questions replayed for follow-ups, 0 disables the replay.
|===
