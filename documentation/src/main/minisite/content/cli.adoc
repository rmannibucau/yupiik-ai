= CLI
:minisite-index: 150
:minisite-index-title: CLI
:minisite-index-description: The tui interactive interface and the run headless command.
:minisite-index-icon: terminal
:minisite-keywords: cli, tui, run, commands
:minisite-breadcrumb: Home[index.html] > CLI

yca splits its CLI into two interactive frontends and automation-oriented
commands. The `cli` and `tui` commands each start a session in front of the same
agent:

* `cli` is a plain-terminal REPL: streamed ANSI-colored output, sessions, todos,
  approval/feedback gates and slash commands.
* `tui` is a full-screen interface (TamboUI): markdown transcript, token gauges,
  a thinking stream, approval modals and an editable plan (`/editplan`).

For automation, `run` executes a single headless prompt and prints the result on
stdout. `completion bash` generates the bash completion script. `code-graph-index`
builds a binary xref:features/code-graph-index.adoc[code graph index] from a jar
for fast symbol lookups.

The complete generated reference for every command and its options (including
`cli.*`, `tui.*` and `run.*`) is on the xref:cli/index.adoc[All commands] page.

Example:

[source,bash]
----
export OPENAI_API_KEY=sk-...
java --enable-native-access=ALL-UNNAMED -jar tui/target/tui-1.0.0-SNAPSHOT-fatjar.jar \
  run --prompt "explain the pom.xml" --yca-provider-model gpt-5-mini
----

TIP: The structural code graph (enabled by default) uses the `javac` API and
therefore needs a JDK (not a plain JRE). No extra JVM flags are required.

TUI options (`tui.*`), cli options (`cli.*`) and run options (`run.*`) are
documented on their xref:cli/index.adoc[command pages].
